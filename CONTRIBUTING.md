# Contributing to Trussium

Trussium is developed in public. Contributions to the runtime, Kubernetes
Operator, Helm chart, and this documentation portal are welcome.

## Where to contribute

| Component | Repository |
| --- | --- |
| Runtime | [trussium](https://github.com/trussiumhq/trussium) |
| Kubernetes Operator | [trussium-operator](https://github.com/trussiumhq/trussium-operator) |
| Helm chart | [trussium-helm](https://github.com/trussiumhq/trussium-helm) |
| Project website and documentation portal | [trussiumhq.github.io](https://github.com/trussiumhq/trussiumhq.github.io) |

## Reporting issues

Use the issue tracker in the repository that owns the affected component.
Before opening an issue, search existing issues and provide a clear description,
reproduction steps where applicable, expected behavior, and observed behavior.

Do not report vulnerabilities through public issues. Follow the
[security policy](SECURITY.md) instead.

## Submitting changes

1. Open an issue before substantial changes so maintainers and contributors can
   discuss scope and design.
2. Create a focused pull request against the relevant repository.
3. Include tests and documentation for behavior changes.
4. Keep commits and pull requests limited to one coherent change.
5. Respond to review feedback and keep the branch current with the target
   branch.

By contributing, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Design and governance

Architecture decisions and project direction are documented in the component
repositories. Project-wide decision-making and maintainer responsibilities are
described in [GOVERNANCE.md](GOVERNANCE.md).
